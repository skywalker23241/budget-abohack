PennyPeek 向导可视化验证

欢迎页 + 5 步向导，在桌面、手机、小屏、横屏、深色模式下走查。35 张主流程/试记截图已更新为本轮优化后的界面。新增底部欢迎弹层、分段进度、44px 触控按钮、提示区和小屏自适应高度。

主流程通过：25 个步骤卡片均在视口内、无横向溢出、没有遮挡高亮目标。各配置下前进/返回、完成、刷新保持关闭、Esc、试记取消后恢复均正常；没有浏览器运行时异常，导览及取消试记前后账本内容一致。

移动端专项验证结果：320、390、430px，含深色与减少动态效果设置；触控尺寸、按钮可见、键盘试记及 16px 高亮间距均通过。类型检查和生产构建通过。

覆盖范围：本地默认示例账本，桌面浏览器模拟视口与系统主题；未覆盖真实 iOS / Android 设备、软键盘、空账本及实际保存一笔后的体验。补充结果 edges.json 与 landscape-fixture.png 为上轮检查证据。

建议优化 · 按优先级

优先处理

高亮按钮的交互规则不一致

第一步「记一笔」和最后一步「设置」可点击；「新增预算」「新增目标」虽然同样高亮，点击却被遮挡层拦截。容易让用户以为按钮失灵。

建议：给预算、目标也提供打开表单后恢复导览的行为，或明确标注本步仅介绍、结束后操作。

卡片内已增加「试记一笔」，键盘可聚焦并按 Enter 打开表单；关闭后继续第二步。

建议：320、390、430px 宽度验证通过。步骤说明使用 aria-live 通知读屏。

优先处理

完成后缺少开始记账的落点

「完成向导」关闭卡片后仍停留在 /app/goals。当前默认显示示例数据，向导没有解释如何转为自己的账本。

建议：结束时提供明确的「开始记账」入口，并说明当前为示例账本；若要清理示例数据，应由用户主动选择并确认。

建议：若设计意图是不再自动提醒，可改为「跳过导览」；若确实是稍后继续，分别保存跳过、完成及当前步骤。

文案校准

界面出现「本地加密存储」

桌面侧栏显示「本地加密存储」，仓库 README 说明浏览器存储不是加密保险箱，数据默认使用 localStorage。

建议：统一改成「数据保存在本机」或「本地存储」，与真实能力保持一致。
